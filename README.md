# ASIC Design Flow Scripts

A collection of scripts, configurations, and project templates for ASIC digital design, including:

* Logic synthesis (Cadence Genus)
* Physical implementation / Place & Route (Cadence Innovus)
* Timing simulation (Cadence Xcelium)
* Constraints and technology setup
* Design kit organization
* Reports, logs, and checkpoints

The repository is organized to keep source files, generated data, scripts, and technology-specific resources separated.

## `constraints/`

Contains all design constraints.

Contents include:

* Generic `.sdc` timing constraint files
* Basic `.view` files for each supported technology
* Cell-specific `.view` files (when required)
* `cts/`
* Clock Tree Synthesis (`ccopt`) configuration files

---

## `docs/`

Directory containing symbolic links to useful documentation.

Instead of copying documentation, symbolic links are created to Cadence manuals and Design Kit documentation.

Cadence installations usually provide documentation in HTML format, but sometimes having direct access to the PDF manuals is much more convenient.

Example:

```bash
mkdir  ~/Virtuosodocs/ 

find  /apps/CADENCE/IC251/doc/  \
	-type f \
	-name  "*.pdf"  \
	-exec ln -s {} ~/Virtuosodocs/ \;
```

The same approach can be used for different Cadence tools by replacing the installation directory, for example:

* IC
* Genus
* Innovus
* Virtuoso

It can also be used for PDK/Design Kit documentation.

---

## `layout/`

Stores the Place & Route results.

Each design has its own subdirectory containing:

* Innovus checkpoint databases (`.enc`)
* Timing reports
* Area reports
* Power reports
* Final Verilog netlists
* SDF files
* DEF files
* GDS files
* Other implementation outputs

The `.enc` checkpoint allows an Innovus session to be restored without rerunning the complete flow.

---

## `lib/`

Contains symbolic links to Design Kit library files.

Unlike `docs/`, these links are created manually according to the current debugging needs.

Typical use cases include:

* Inspecting a specific standard cell
* Viewing transistor-level implementations
* Checking library views
* Exploring characterization files

Contains all automation scripts.

### `physical/`

TCL scripts implementing each stage of the physical design flow, including:

* Floorplanning

* Routing
* Optimization

### `pins/`

Pin assignment files used during Place & Route.

Each design can have its own pin configuration.

### Main scripts

#### `Setup.tcl`

Global environment configuration.

This script contains technology-dependent settings selected through a technology switch and is shared by both synthesis and physical implementation flows.

---

#### `logic_synt.tcl`

Main Logic Synthesis flow.

Used with Cadence Genus.

---

#### `phy_synt.tcl`

Main Physical Synthesis / Place & Route flow.

Used with Cadence Innovus.

---

#### `dont_use.tcl`

Defines standard cells that should not be used during synthesis or optimization.

---

#### `xrun.conf`

Configuration file for Cadence Xcelium.

Typical settings include:

* GUI or batch mode
* Timescale
* Simulator version
* Top module
* Additional simulation options

---

#### `run.sh`

Main Bash launcher script.

A symbolic link to this script is placed in the repository root, allowing the complete flow to be executed without changing directories.

# Running `run.sh`

The project provides a single entry point (`run.sh`) to execute simulations, synthesis, Place & Route, and utility commands.

Before executing any flow, the script:

* Sets the project root directory.
* Loads the required Cadence modules (Genus and Innovus by default).
* Enables 64-bit Cadence tools (`CDS_AUTO_64BIT=ALL`).
* Exports environment variables pointing to the main project directories.
* Reads the selected technology node from `.tech_node` (default: `XH180`).

---

### Selecting the Technology Node

The current technology is stored in the `.tech_node` file.

To change it, run:

```bash

./run.sh  cfg
```

Available technology nodes include:

* `XH180`
* `TC65N`
* `22FDX`

The selected technology will be used by both the logic synthesis and physical implementation scripts.

---

### General Syntax

```bash

./run.sh <command> <design_name> [extra_arguments]
```

Example:

```bash

./run.sh  g  alu
```

Runs logic synthesis for the design `alu`.

---

## Available Commands

| Command | Description |
|---------|-------------|
| `x` | HDL simulation using Xcelium |
| `xs` | Post-synthesis simulation |
| `xl` | Post-layout (Post-P&R) simulation with SDF annotation |
| `xg` | HDL simulation with Xcelium GUI |
| `xc` | Compile design and testbench only |
| `xe` | Elaborate design only |
| `g` | Run scripted logic synthesis (Genus) |
| `gg` | Open Genus interactively |
| `i` | Run scripted Place & Route (Innovus) |
| `id <checkpoint>` | Open an Innovus checkpoint database |
| `ii` | Open Innovus interactively |
| `all` | Execute the complete flow (logic synthesis + Place & Route) |
| `cfg` | Change the active technology node |
| `-h` | Show command help |
| `-dbg` | Print debug information |

## Examples

### HDL Simulation

```bash

./run.sh  x  alu
```

Runs the RTL simulation of `alu.sv` together with `alu_tb.sv`.

---

### Post-Synthesis Simulation

```bash

./run.sh  xs  alu
```

Runs simulation using the synthesized netlist generated by Genus.

---

### Post-Layout Simulation

```bash

./run.sh  xl  alu
```

Runs simulation using the final Place & Route netlist and annotates delays through the configured SDF command file.

---

### Logic Synthesis

```bash

./run.sh  g  alu
```

Launches Cadence Genus using `scripts/logic_synt.tcl`.

---

### Physical Implementation

```bash

./run.sh  i  alu
```

Launches Cadence Innovus using `scripts/phy_synt.tcl`.

---

### Full Design Flow

```bash

./run.sh  all  alu
```

Executes the complete automated flow:

1. Logic synthesis (Genus)
2. Physical implementation (Innovus)

---

### Open an Innovus Checkpoint

```bash

./run.sh  id  alu  route
```

Loads the checkpoint:

```text

layout/alu_<tech_node>/checkpoint/alu_route.enc
```

This is useful for resuming the implementation flow from a previously saved stage.

---

## File Validation

Before executing a command, `run.sh` verifies that all required files and directories exist.

For example, it checks:

* RTL source files
* Testbenches
* Synthesized netlists
* Place & Route netlists
* Innovus checkpoints

If any required file is missing, the script aborts and reports the missing resource instead of launching the corresponding Cadence tool.

---

## Notes

* Xcelium is loaded only for simulation-related commands.
* Genus and Innovus modules are loaded during script initialization.
* All tool execution takes place inside the `work/` directory to keep the project root clean.
* Tool logs are written to the `logs/` directory.
* Generated synthesis and implementation outputs are stored under `synthesis/` and `layout/`, respectively.
